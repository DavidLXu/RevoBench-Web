项目介绍

RevoBench 探索用 Agent 完成灵巧操作 benchmark 的构建与验证。我们基于高保真的数字资产搭建仿真环境，由 Agent 编写任务、生成示例轨迹，并根据执行结果检查和修改实现。

示例轨迹用于验证任务能否完成，也用于发现问题。物体到达目标位置时，手臂仍可能出现不自然的绕行，或依靠拇指背部抓持。我们结合执行记录检查姿态、运动连续性与接触方式，并要求机器人从默认姿态出发，完成后回到默认姿态。

后续将由 Agent 参与构建评测程序，在固定的任务条件下比较不同 agent-based policy。环境、示例轨迹和评测接口将整理为统一的任务包，方便新的 Agent 独立运行和复现结果。

Agent 评测指标

离线和在线模式分别报告。先看同一任务的物理成功率，再比较完成任务的代价和动作质量。离线模式累计暂停推理、回滚和重试的成本。在线模式按真实经过时间计时，只有机械臂实际等候新指令的时段计入等模型时间。

指标方向如何计算
首次尝试成功率 ↑ 越高越好 首次尝试通过完整物理验收的初态数 ÷ 全部测试初态数。抓滑后可以当场重抓。一旦回滚、重置或回合结束，首次尝试即结束。
给定预算内的解题率 ↑ 越高越好 在预算内通过完整物理验收的初态数 ÷ 全部测试初态数。首版每个初态的预算为实际总用时 ≤ 5 分钟且规划总量 ≤ 25 万 token。每个初态最多计一次成功。
规划总 token 数 ↓ 越低越好 累计所有规划调用的输入和输出，包含思考 token。按服务回执计数，思考 token 只计一次。缺失的用量标为未记录。
等模型的时间（秒） ↓ 越低越好 累计因等待模型而暂停仿真，或上一段动作已结束、机械臂只能等待新指令的实际秒数。边执行边推理的时段不计入。
模型与执行总用时（秒） ↓ 越低越好 从开始求解到任务结束的实际秒数，包含规划、执行、等待和重试。推理与动作同时进行时只计一次。
纯执行用时（秒） ↓ 越低越好 按仿真时钟累计各次尝试中执行动作的时长，包含任务要求的持稳和释放观察，扣除纯等模型的时段。
拟人程度 ↑ 越高越好 人工按原速回放评估抓姿、手腕姿态和双手分工是否自然。
模型调用次数 ↓ 越低越好 每发起一次模型请求计一次，包含首次规划、后续修正和重试。一次回复给出多个移动目标仍算一次。

预算从 Agent 收到任务和初始观测时起算，到首次通过完整物理验收为止。等待、失败尝试和重试都累计，回滚不会重置预算。token 包含全部调用的输入、输出和思考用量，思考 token 只计一次。超时、超量或未解出的初态仍计入分母。用量缺失且无法核实是否达标的初态单列，保留在分母中。

任务怎样算成功？初态怎样变化？

175 项任务中，29 项已登记评分脚本，22 项有物理与数据双验收记录，10 项启用了物体摆位随机化门控。每项任务分别定义目标、允许的接触、松手或持稳条件，以及初态可变范围。拟人程度另由人工查看原速回放。

种子怎么选？多个物体怎样随机摆放？

运行者用 --seed 指定整数，默认 0。启用 --randomize 后，当前接入的 10 项在 reset 时按任务声明的范围采样整组物体的 X、Y 平移，保持组内相对位置。每个候选布局由任务自己的可达性、接近路径或碰撞检查筛选，最多尝试 32 次；全部被拒则报告初态生成失败。记录保存种子、实际偏移和拒绝原因。

例如插杆与孔座同移，厨房的锅、食材和碗也同移。公开归档的 10 个随机成功实例中，9 个用 seed 1，电钻用 seed 4。它们是可复现的参考实例。要比较不同 Agent 的成功率，应事先冻结有效初态清单，让各方法跑同一批，保留失败结果。

材质、灯光与相机安装位姿属于外观随机化，可用 --appearance-seed 单独控制，默认沿用本回合的 seed。每个物体独立平移或转动、替换几何、改变摩擦或质量，都需要任务单独声明范围、约束并重新验证。

评分脚本读什么？

脚本从逐帧物体位姿、接触力和终态检查任务条件，并输出各项通过或失败。插杆检查插入深度、接触力和松手稳定；搬箱还要检查双手是否共同承托、落点和箱体姿态。现有部分脚本（例如插杆）还依赖参考 planner 的阶段名或完成标志。用于任意外部 Agent 的正式评分前，需要改为从物理轨迹本身识别这些阶段。
